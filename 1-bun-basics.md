## 🔥 What is Bun

Bun is a modern JavaScript runtime similar to NodeJS — a tool used to run JavaScript code. It was created by **Jarred Summer** as a replacement for NodeJS.

- Built using the **Zig** programming language
- Based on **WebKit JavaScript Core** (not V8 like NodeJS)
- Free and Open Source

> Official website: https://bun.sh/

### Why Bun?

- **Faster** than NodeJS
- Supports **JavaScript and TypeScript** out of the box — no extra setup needed
- **All-in-one tool**: Runtime, Test Runner, and Package Manager are all built-in

## 🔷 TypeScript & JSX

- #### TypeScript

  Bun supports TypeScript natively by default. The `jsconfig.json` file (generated by `bun init`) can be renamed to `tsconfig.json` for TypeScript projects. TypeScript is also included as a default dev dependency in `package.json`.

- #### JSX / TSX

  Bun also supports **JSX** and **TSX** (popularized by React). Install the required dependency first:

  ```bash
  bun add react
  bun add @types/react --dev
  ```

  ```tsx
  const hello = <h1>Hello World!</h1>
  console.info(hello)
  ```

## 🌿 Environment Variables

Bun automatically reads `.env` files — no external library required. Access variables using the `process` object:

```ts
console.log(process.env.DATABASE_HOST);
```

- #### NODE_ENV Support

  If the `NODE_ENV` environment variable is set, Bun will automatically load the corresponding `.env.{NODE_ENV}` file.

  | NODE_ENV value | File loaded           |
  |----------------|-----------------------|
  | `production`   | `.env.production`     |
  | `dev`          | `.env.dev`            |

## 📦 Package Manager

Bun has a built-in package manager compatible with NPM. No additional installation required.

- #### Install Dependencies

  ```bash
  bun install
  ```

  > Bun stores lock information in `bun.lockb` (binary file) instead of `package-lock.json` for faster reads.

  To install **production dependencies only**:

  ```bash
  bun install --production
  ```

- #### Manage Dependencies

  | Action                   | Command               |
  |--------------------------|-----------------------|
  | Add dependency           | `bun add <name>`      |
  | Remove dependency        | `bun remove <name>`   |
  | Update all dependencies  | `bun update`          |

- #### Cache

  Downloaded packages are cached at `$USER/.bun/install/cache`. Packages with the same version are reused from cache, speeding up future installs.

## 🧪 Test Runner

Bun has a **built-in Test Runner** compatible with **Jest**. If you're familiar with Jest, your existing test code will work in Bun.

```bash
bun test
```

Run tests in watch mode:

```bash
bun test --watch
```

- #### Example

  `src/hello.ts`
  ```ts
  export function sayHello(name: string): string {
    return `Hello ${name}`;
  }
  ```

  `test/hello.test.ts`
  ```ts
  import { describe, it, expect } from "bun:test"
  import { sayHello } from "../src/hello"

  describe('Bun Test Runner', () => {
    it('should support unit test', async () => {
      const response = sayHello('Dzaru')
      expect(response).toBe('Hello Dzaru')
    })

    it("should support unit test with budi", async () => {
      const response = sayHello("Budi");
      expect(response).toBe("Hello Budi");
    });
  })
  ```

  `Expected output:`

  ```
  bun test v1.3.12 (700fc117)

  test/hello.test.ts:
  ✓ Bun Test Runner > should support unit test [0.34ms]
  ✓ Bun Test Runner > should support unit test with budi

   3 pass
   0 fail
  ```

## 🗂️ Workspace

Bun Package Manager supports **Workspaces** — a feature for managing multiple packages/sub-projects within a single repository.

- #### Setup

  1. Create a `packages/` folder for sub-packages
  2. Initialize each sub-package with `bun init`
  3. Declare workspaces in the root `package.json`

  ```json
  {
    "name": "study-bun",
    "workspaces": [
      "packages/*"
    ]
  }
  ```

  4. Run `bun install` to symlink all sub-packages into `node_modules`

- #### Using Sub-packages

  ```ts
  import { User } from "user/user.ts";

  const user = new User("John Doe");
  console.log(user.name); // John Doe
  ```

## ⚙️ Bunfig Configuration

Bun can be configured using `bunfig.toml`. While most settings can be placed in `package.json` or `tsconfig.json`, Bun-specific settings go here.

> Reference: https://bun.sh/docs/runtime/bunfig

`Example bunfig.toml:`

```toml
logLevel = "debug"

[test]
root = "./test"
coverage = true
```

## 📚 Bun Standard Library

Bun provides its own Standard Library accessible via the global `Bun` variable. Note that Bun Standard Library code **will not run in NodeJS**.

- #### HTTP Server

  > Reference: https://bun.sh/docs/api/http

  ```ts
  Bun.serve({
    port: 3000,
    fetch: (request) => {
      const url = new URL(request.url);
      const name = url.searchParams.get("name") || "World";
      return new Response(`Hello ${name}`);
    },
  });
  ```

  | URL                                   | Response       |
  |---------------------------------------|----------------|
  | `http://localhost:3000`               | `Hello World`  |
  | `http://localhost:3000/?name=Dzaru`   | `Hello Dzaru`  |

- #### File I/O

  > Reference: https://bun.sh/docs/api/file-io

  ```ts
  const file = Bun.file(".env");
  const content = await file.text();
  console.log(content);

  await Bun.write(".env.test", content);
  ```

- #### Hashing

  > Reference: https://bun.sh/docs/api/hashing

  ```ts
  const password = "secret";

  const hash = await Bun.password.hash(password, {
    algorithm: "bcrypt",
    cost: 10,
  });

  const result = await Bun.password.verify(password, hash, "bcrypt");
  console.log(result); // true
  ```

- #### Semantic Versioning

  > Reference: https://bun.sh/docs/api/semver

  Bun includes a built-in library for semantic versioning checks.

- #### Utilities

  > Reference: https://bun.sh/docs/api/utils

  ```ts
  console.log(Bun.version);           // 1.3.12
  console.log(Bun.revision);          // 700fc117...
  console.log(Bun.env.DATABASE_HOST); // localhost
  ```

## 🌍 Bun Ecosystem

Bun is designed to be **compatible with the NodeJS ecosystem** from the start, meaning most NodeJS/NPM libraries work in Bun without changes.

Supported NodeJS libraries include:

| Library       | Purpose       | Install                       |
|---------------|---------------|-------------------------------|
| **Winston**   | Logging       | `bun add winston`             |
| **ExpressJS** | HTTP Server   | `bun add express`             |
| **Zod**       | Validation    | `bun add zod`                 |
| **Prisma ORM**| Database ORM  | `bun add prisma --dev`        |

Here is an implementation example: 

- #### Winston (Logging)

  ```ts
  import winston from "winston";

  const logger = winston.createLogger({
    format: winston.format.json(),
    level: "debug",
    transports: [new winston.transports.Console()],
  });

  logger.info("Hello World");
  logger.warn("Hello World");
  logger.error("Hello World");
  ```

- #### ExpressJS

  ```ts
  import express from "express";

  const app = express();

  app.get("/", (req, res) => {
    res.send("Hello World!");
  });

  app.listen(3000, () => {
    console.log("Server started on port 3000");
  });
  ```

- #### Zod

  ```ts
  import { z } from "zod";

  const loginValidation = z.object({
    username: z.string().min(1).max(50).email(),
    password: z.string().min(1).max(50),
  });

  loginValidation.parse({
    username: "dzaru@example.com",
    password: "dzaru1234",
  });
  ```

- #### Prisma ORM

  Initialize and generate:

  ```bash
  bun add prisma --dev
  bunx prisma init --datasource-provider mysql
  bunx prisma migrate dev
  bunx prisma generate
  ```

  `Example schema (prisma/schema.prisma):`

  ```prisma
  model Contact {
    id    Int    @id @default(autoincrement())
    name  String @db.VarChar(100)
    phone String @db.VarChar(20)
    email String @db.VarChar(100)

    @@map("contacts")
  }
  ```

  `Usage:`

  ```ts
  import { PrismaClient } from "@prisma/client";

  const prisma = new PrismaClient();

  const contact = await prisma.contact.create({
    data: {
      name: "Dzaru Rizky Fathan Fortuna",
      email: "dzaru@example.com",
      phone: "081234567890",
    },
  });

  console.log(contact);
  ```

## 🔨 Build

Bun can bundle and compile your project into a single output file.

```bash
bun build input.ts --outdir dist
```

| Flag                  | Description                                    |
|-----------------------|------------------------------------------------|
| `--outdir <folder>`   | Output directory                               |
| `--minify`            | Minify the output for smaller file size        |
| `--sourcemap`         | Generate source map for debugging              |

`Example:`

```bash
bun build hello.ts --outdir dist --minify --sourcemap
```

```
Bundled 2 modules in 24ms

  hello.js      152 bytes  (entry point)
  hello.js.map  466 bytes  (source map)
```

## 📦 Executable File

Bun can compile your project into a **standalone executable** — including all dependencies and the Bun runtime itself. No Bun installation is needed to run the output.

> Use `--outfile` instead of `--outdir` when using `--compile`.

```bash
bun build express.ts \
  --compile \
  --minify \
  --sourcemap \
  --outfile build/express \
  --target=bun-linux-arm64
```

`Run on any machine (e.g. Docker):`

```bash
docker run --rm -p 3000:3000 -v $(pwd)/build:/app ubuntu:22.04 /app/express
# Server started on port 3000

curl "http://localhost:3000?name=Dzaru"
# Hello Dzaru
```

## 💡 Best Practices

- #### Project Setup
  - Use `bun init` to scaffold projects; choose `.ts` entrypoint for TypeScript projects
  - Rename `jsconfig.json` to `tsconfig.json` for full TypeScript support
  - Use `bunfig.toml` for Bun-specific configuration (test root, coverage, log level)

- #### Dependencies
  - Use `bun install --production` in production environments to skip dev dependencies
  - Use `bun update` regularly to keep packages up to date
  - Leverage the `bun.lockb` binary lock file for faster, reproducible installs

- #### Development
  - Use `--watch` flag during development to avoid manually restarting the server
  - Use `bunx` instead of `npx` for running package executables
  - Use **Workspace** feature for monorepo setups with multiple sub-packages

- #### Testing
  - Bun Test Runner is Jest-compatible — migrate existing Jest tests without code changes
  - Enable `coverage = true` in `bunfig.toml` to track test coverage
  - Use `bun test --watch` during development for instant feedback

- #### Building
  - Always use `--minify` and `--sourcemap` together when building for production
  - Use `--compile` to produce a self-contained binary for deployment without Bun installed
  - Specify `--target` when cross-compiling (e.g., `bun-linux-arm64` for Linux ARM)
